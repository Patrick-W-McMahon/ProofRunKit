# Windows x64 installer (MSI)

This page records the installer-technology choice (#40), the code-signing decision
(#41), and how to build and inspect the 64-bit MSI (#37). The 32-bit installer and
Win32 presets are documented in [installer-windows-x86.md](installer-windows-x86.md)
(#38, #39).

There are no GitHub Actions workflows; the MSI is built locally from the
`windows-msvc-x64-release` preset.

## Decisions

| Topic | Decision | Ticket |
| --- | --- | --- |
| Technology | **WiX Toolset v4** MSI, pinned to **4.0.6** (still published on NuGet). | #40 |
| Install scope | Per-machine. | #36, #37 |
| x64 destination | `%ProgramFiles%\ProofRunKit` (`ProgramFiles64Folder\ProofRunKit`, typically `C:\Program Files\ProofRunKit`). | #37 |
| PATH | Optional feature **AddToPath**, **included by default**. | #37, #40 |
| Start Menu | A "ProofRunKit" folder with a Help shortcut and a link to the repository. | #37, #40 |
| Add/Remove Programs | Name `ProofRunKit`, publisher `ProofRunKit`, URL below. | #37 |
| Signing | **Deferred.** Packages ship unsigned. Revisit later; spending needs an explicit OK. | #41 |
| Packers | None. The MSI uses ordinary cabinet compression; `proofrunkit.exe` is the plain MSVC output. | #22 |

Repository: [https://github.com/Patrick-W-McMahon/ProofRunKit](https://github.com/Patrick-W-McMahon/ProofRunKit).

### Why WiX v4 MSI (not Inno Setup)

WiX v4 produces a standard MSI with first-class per-machine install, Add/Remove
Programs, a stable `UpgradeCode` plus `MajorUpgrade`, and a conventional silent
install via `msiexec`. That matches the expectations for a system-wide tool under
Program Files.

Inno Setup is a capable alternative when a single EXE installer is preferred. It
handles per-machine install, optional PATH, Start Menu icons, Add/Remove Programs,
and silent flags (`/VERYSILENT /NORESTART`), but it is not an MSI and
upgrade/ARP behaviour is more custom.

WiX v5 and later remain available (`dotnet tool install --global wix` currently
installs a post-v4 release). This project stays on v4 because that is the chosen
toolset and 4.0.6 is still obtainable. The authoring uses the v4 schema
(`http://wixtoolset.org/schemas/v4/wxs`).

CMake's CPack WIX generator can target WiX v4 (`CPACK_WIX_VERSION=4`, CMake 3.30+).
This project invokes `wix build` directly so the destination, UpgradeCode, optional
PATH feature, and silent flags stay in first-party authoring under
`installer/windows/ProofRunKit-x64.wxs`.

### Unsigned packages (#41)

The installer and the installed `proofrunkit.exe` are not code-signed. Norton,
Microsoft SmartScreen, and similar tools may still warn on first run even when
the binary itself is kept stable (#22). Signing options (Azure Artifact Signing,
an OV or EV certificate) remain on #41 and need an explicit spending OK before
anything is purchased.

## UpgradeCode

The x64 product line uses this UpgradeCode. **Do not change it.** Newer versions
that share it replace older ones via `MajorUpgrade`. The 32-bit installer (#38) uses a different UpgradeCode: `{A31020BF-969A-4139-9FA1-82E044AC31F5}`.

```
{FB358981-835D-421D-8634-BA130FE100A2}
```

`ProductCode` is generated by WiX on every build, which is what `MajorUpgrade`
expects. The MSI ProductVersion comes from the CMake project version
(`project(ProofRunKit VERSION 0.1.1)` today), which is a three-part
`Major.Minor.Patch` value. MSI ignores a fourth version field, so keep bumps in
the first three parts.

A newer installer refuses to downgrade: it shows *A newer version of ProofRunKit
is already installed. Uninstall it before installing this version.*

## What is installed

| Item | Location |
| --- | --- |
| `proofrunkit.exe` | `%ProgramFiles%\ProofRunKit` |
| `prk.cmd` | Same folder. The `prk` command: a text shim that runs `proofrunkit.exe` from this folder with every argument and returns its exit code (#93). `proofrunkit.exe` is the only executable installed; an upgrade removes the `prk.exe` copy that earlier packages installed. |
| `LICENSE.txt` | Same folder. The repo-root [`LICENSE`](../LICENSE) (verbatim Apache License 2.0), packaged unchanged (#58). |
| `NOTICE.txt` | Same folder. The repo-root [`NOTICE`](../NOTICE), per Apache-2.0 section 4(d) (#58). |
| Start Menu shortcuts | `ProofRunKit Help` (opens a console with `proofrunkit.exe --help`) and `ProofRunKit on GitHub.url` |
| Optional PATH entry | The install directory is appended to the **system** PATH |

`proofrunkit_selftest`, PDBs, static libraries, and project test suites are **not**
packaged. The installed executable stays the same stable runner; tests are not
compiled into it.

The "Add to PATH" feature is Level 1, so it is selected by default (a CLI tool is
awkward without it). Uncheck it in the feature tree, or pass `REMOVE=AddToPath` on
a silent install, to skip it. Uninstall removes the PATH entry (`Permanent="no"`).

## Silent install, uninstall, and logging

Run from an elevated command prompt. `/qn` is fully silent; `/qb` shows a progress
bar; `/l*v` writes a verbose log.

```bat
rem Install, including PATH (the default)
msiexec /i ProofRunKit-0.1.1-win-x64.msi /qn /l*v %TEMP%\ProofRunKit-install.log

rem Install without adding PATH
msiexec /i ProofRunKit-0.1.1-win-x64.msi /qn REMOVE=AddToPath

rem Uninstall this MSI (or use Add/Remove Programs)
msiexec /x ProofRunKit-0.1.1-win-x64.msi /qn

rem Upgrade: install a newer MSI with the same UpgradeCode; MajorUpgrade replaces the older version
msiexec /i ProofRunKit-0.2.0-win-x64.msi /qn
```

The filename's version number tracks the CMake project version.

## Prerequisites

In addition to the [Windows build prerequisites](building-windows.md) (Visual Studio
2026 with the C++ workload, CMake 3.21+, Git):

| Tool | Version | Notes |
| --- | --- | --- |
| .NET SDK | 6 or later (8 recommended) | Required to install the WiX .NET tool. The C++ workload does not always include it. |
| WiX Toolset | **4.0.6** | `dotnet tool install --global wix --version 4.0.6` |
| WixToolset.UI.wixext | **4.0.6** | `wix extension add -g WixToolset.UI.wixext --version 4.0.6` |

The build and verify scripts **do not** install these tools. If WiX is missing they
print the commands above and exit. After installing the global tool, close and
reopen the terminal so `%USERPROFILE%\.dotnet\tools` is on PATH.

`winget install Microsoft.DotNet.SDK.8` is a convenient way to get the SDK.

## Building the MSI

From the repository root, after the working tree is clean:

```powershell
.\installer\build-msi-x64.ps1
```

The script aborts if the working tree is dirty (it never stashes, resets, or
discards changes). It enters the Visual Studio x64 developer shell, configures and
builds `windows-msvc-x64-release`, then builds the `package-msi` target and prints
the output path:

```
build\windows-msvc-x64-release\installer\ProofRunKit-<version>-win-x64.msi
```

The same steps by hand:

```powershell
cmake --preset windows-msvc-x64-release
cmake --build --preset windows-msvc-x64-release
cmake --build --preset windows-msvc-x64-release --target package-msi
```

`cmake --build --preset windows-msvc-x64-msi` is equivalent to the last command
(it also depends on `proofrunkit`, so it will build the executable if needed).

## Checksum and releases (`prk -update`)

`build-msi-x64.ps1` also writes `ProofRunKit-<version>-win-x64.msi.sha256` (`<sha256>  <file name>`, ASCII) next to
the MSI, and `verify-msi-x64.ps1` checks it. **Every GitHub release must attach the MSI and its `.sha256`**
(names as built, or `ProofRunKit-x64-<version>.msi` + `.sha256`); `prk -update` refuses an MSI without a matching
checksum. See [update.md](update.md#publishing-a-release-what-prk--update-needs).

## Verifying without installing

```powershell
.\installer\verify-msi-x64.ps1
.\installer\verify-msi-x64.ps1 -MsiPath path\to\ProofRunKit-0.1.1-win-x64.msi
```

This is read-only: it never runs `msiexec /i`. It inspects the MSI with the
Windows Installer COM API (Directory, Property, Feature, File, Environment, and
LaunchCondition tables) and then performs an administrative extraction
(`msiexec /a ... TARGETDIR=<temp>`) to confirm `proofrunkit.exe` (the only `.exe`), `prk.cmd` (calling `proofrunkit.exe` with `%*`), `LICENSE.txt`,
and `NOTICE.txt` are present and that no `prk.exe` is packaged. The Directory table is what proves the real destination is
`ProgramFiles64Folder\ProofRunKit`; the administrative `TARGETDIR` is only a
temporary unpack folder and is deleted afterwards.
